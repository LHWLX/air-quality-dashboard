# 项目提交与答辩流程

## 一 提交前准备

1. 安装 JDK 25，执行 `java -version` 确认版本。
2. 用 IntelliJ IDEA 打开项目并等待 Maven 下载依赖。
3. 把 Git 作者改为自己的姓名和邮箱。
4. 补全 AI 使用记录和答辩 PPT 中的个人信息。

## 二 最终验收

按以下顺序执行，每一项都通过后再提交：

```powershell
mvn test package
java -jar target/air-quality-dashboard-1.0.0.jar
```

1. 打开 `http://localhost:8080/`，确认首页无报错。
2. 默认应显示最近 30 天、6 个城市、180 条记录。
3. 只选北京和上海，切换到 NO₂，点击“更新看板”。
4. 确认折线图只剩两条城市曲线，柱状图只有两个城市。
5. 确认环形图和 4 个摘要指标同步变化。
6. 翻到表格第 2 页，再点击一条记录的“详情”。
7. 打开 Swagger，分别执行 A1、A2、A3、A4。
8. 打开 H2 控制台，查询记录总数应为 720。
9. 用浏览器设备工具检查 1440px、768px、390px 三种宽度。

## 三 推送仓库

在 GitHub、Gitee 或学校 Git 服务新建空仓库，然后执行：

```powershell
git branch -M main
git remote add origin 你的仓库地址
git push -u origin main
```

提交前检查：

```powershell
git status
git log --oneline
```

`git status` 应没有未提交源码，`git log` 应至少有 10 条明确提交。

## 四 打包提交物

最终提交内容建议如下：

```text
城市空气质量监测看板
├─ 项目源码或 Git 仓库链接
├─ README.md
├─ database/README.md
├─ docs/AI使用记录表.md
├─ docs/提交与答辩流程.md
└─ docs/城市空气质量监测看板答辩.pptx
```

不要提交 `target`、`.m2`、`.idea` 和本地 `data` 数据库目录。

## 五 现场演示顺序

总时长控制在 5 至 7 分钟。

1. 30 秒：说明项目目标和技术栈。
2. 90 秒：演示城市、日期和指标筛选，观察三类图表联动。
3. 45 秒：演示表格分页和单条详情。
4. 60 秒：打开 Swagger 执行一个明细接口和一个统计接口。
5. 45 秒：打开 H2 控制台，证明数据来自数据库且共 720 条。
6. 60 秒：讲解 Controller、Service、Repository 分层和数据初始化规则。
7. 30 秒：展示测试结果和 Git 提交记录。

## 六 需要能回答的问题

**为什么不用 Vue 或 React？**

课程明确要求原生 HTML、CSS、JavaScript，因此使用 ES6 模块化思路和 fetch 完成交互。

**数据是不是静态文件？**

不是。首次启动由 Java 程序生成并写入 H2 文件数据库，所有接口都通过 JPA 查询数据库。

**多城市筛选如何实现？**

前端把城市代码用逗号拼接，后端接收列表后通过 JPA Specification 构造 `IN` 条件，并同时叠加日期条件。

**统计接口如何计算？**

Service 按城市分组，对当前指标计算平均值、最大值和最小值，再统计质量等级为“优”或“良”的记录比例。

**为什么 ECharts 不用 CDN？**

项目通过 Maven WebJar 把 ECharts 打进 JAR，现场断网也能正常绘图。

**AI 生成的代码你是否理解？**

需要现场指出一个 Controller、一个 Service 查询方法和前端 `refreshDashboard` 流程，并用自己的语言解释输入、处理和输出。
